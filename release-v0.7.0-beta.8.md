# Braumeister Display Card 0.7.0-beta.8

Adds missing stage keys and distinguishes program pause from final abort:

- Recipe selection: Cancel, Down, Up, **Select**.
- Water prompt: all four visual keys; the unsupported actions remain disabled.
- Pump purging/heating: Cancel requests a pause; it does not claim final abort.
- Pause dialog (interrupt 1 / observed indicator 120): Cancel for final abort,
  Select for resume, with separate confirmations. Resume is limited to 2300.
- Red pause outline/pulse; `program_alarm_animation: false` opts out and reduced
  motion is respected. Browser/device alarm audio is not added or controlled.
- All new text is bundled in eight languages. Existing lower tabs, actuator
  controls, pending animation and heartbeat warning are preserved.

New enabled actions require Companion **0.1.0-beta.6** and experimental Bridge
**0.3.2-control.4-beta.1**. Update the existing local Bridge separately first,
then the Companion through HACS (one HA restart), then this Card through HACS
and reload the dashboard/browser. Preserve all existing YAML/entity mappings.

For purge resume, add `program_control: true` to the Card only when intended.
The Bridge additionally needs `program_control_enabled: true` and
`allow_remote_heating: true`; both server permissions must be satisfied.
Recipe confirmation/pause/final abort do not need the Card's resume opt-in.
The Card enables new actions only if advertised by the matching Companion.
Unsupported actions remain visible but disabled with an explanation.

Water confirmation, start-delay Up/Down, water-prompt cancellation, state 2310
actions and heating-stage resume remain disabled/unimplemented. This beta does
not provide a complete remote brew-start sequence. Existing safety confirmations
remain, and backend validation is authoritative.

Validation: seven Node test scripts, syntax/build/diff checks passed. The matching
Bridge passed 220 tests plus 261 subtests and an emulated ARM64 synthetic smoke
test on an internal Docker network; Companion passed 17 tests. The local command
path still needs hardware validation. No actual device command was generated by
the development tests.

The release asset `braumeister-display-card.js` contains all catalogs. Keep one
HACS JavaScript module resource. Card-only updates require a browser reload,
not an HA restart. Roll back by redownloading the previous Card in HACS and
reloading the browser; keep the existing YAML and remove the new resume opt-in.
